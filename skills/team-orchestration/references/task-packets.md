# 任务包构造规范

派发任何子 agent 前，先判断是无计划模式还是计划对齐模式，再构造一个**自包含的任务包**。子 agent 是 fresh context，它只知道你写进任务包的内容。

同一 lane 的派发按「初次 / 续作 / 重建」三种形态区分（对应 SKILL.md「编排状态与恢复」与 references/workflows.md 配方）：

- **初次执行 / 初次评审** → 完整四要素包（fresh Agent 用）
- **原会话续作（resume）** → 续作任务包（增量，原会话已保有上下文）
- **会话不可恢复后的 fresh fallback** → 重建任务包（完整四要素 + findings，**禁止**只给 delta）

## 无计划模式

没有显式计划文件时，领导者继续按本规范蒸馏任务包。任务包的四要素——目标、约束、相关文件、验收标准——是 executor 的完整要求来源。不要为了假装精确而虚构计划引用。

## 计划对齐模式

用户或执行流程显式指定计划文件时，任务包必须绑定该计划的一个**原生执行单元**，不得由领导者再次任意切片、合并或扩张。任务包额外包含：

- **计划文件**：只读计划的精确路径；
- **原生执行单元**：计划中的任务编号、标题或精确范围；
- **要求来源**：该单元的 brief 文件或原文范围；
- **运行时补充**：BASE commit、已落地的前置接口、领导者裁决、report 路径。

计划原文仍是要求来源。运行时补充只能解决计划编写后才出现的事实，不能覆盖、拓宽或重述其中的精确值。计划格式无法可靠识别时，领导者必须明确给出标题或范围；不能识别原生单元就停止派发并返回领导者，**不得静默切换到无计划模式**。

### Superpowers 计划

对 `superpowers:writing-plans` 生成的计划：

- 一个完整的 `### Task N` 是一次 executor 执行与一次 task-scoped reviewer 的共同单元；
- Task 内的 Step 由同一 executor 按顺序执行，**不得把 Task 内的 Step 再拆成不同 executor 任务包**；
- 可用时先运行 `task-brief PLAN_FILE N`，把输出的 brief 路径作为唯一要求文件；
- 精确代码、常量、命令、测试与预期结果留在 brief 中，不在派发提示里改写第二份；
- executor 不读取整个计划文件，只读取 brief；
- 派发提示只补充该 Task 在项目中的位置、前置 Task 已产出的真实接口、领导者裁决与 report contract。

### 机械就绪检查

计划对齐任务派给 executor 前，领导者逐项确认：

- [ ] 有精确文件或代码锚点；
- [ ] 有明确操作或完整实现内容；
- [ ] 有具体验证命令与预期结果；
- [ ] 前置接口和依赖已解析；
- [ ] 不含待决定的架构、产品或 API 选择。

全部满足才派 executor。任一项不满足就返回领导者裁决或补齐设计；不得通过加入开放式研究、全仓调查、额外设计或宽泛测试来扩大 executor 权责。计划文件保持只读，裁决写入该计划已有的 ledger、mission decision 或任务包运行时补充。

## 结构

每个任务包必含四要素：

```
## 目标
要完成什么，一两句话。动词开头。

## 约束
硬性边界：语言/框架版本、不能动的文件、必须保持的接口、风格规则、
依赖白名单。没有就写「无特殊约束」。

## 相关文件
精确路径清单（含行号或函数名锚点更好）。只列真正相关的，
不要用 glob 把半个仓库扫进去。子 agent 需要更多上下文时让它自己
用 read/grep 探索——探索是廉价的，把整个文件树塞进任务包是昂贵的。

## 验收标准
可机械判定的完成条件：跑什么命令、期望什么输出、哪些测试必须通过。
```

## 规则

1. **禁止粘贴对话历史**。用户的原话、你的思考过程、之前的往返，都不进任务包。任务包是蒸馏产物，不是转发。
2. **禁止「帮我做 X」式的模糊任务包**。X 没法拆成四要素时，说明还没到派发时机——你先设计。
3. **文件路径优先于内容摘录**。让子 agent 自己读文件，只摘录关键的接口签名/约束片段（<20 行）。
4. **一个任务包一个焦点**。同文件的两个独立改动拆成两包；同构批量改动（如「给这 10 个文件加同一类错误处理」）合一包并行派。
5. **研究任务包**要给：具体问题列表（可枚举）、背景（为什么问，<100 字）、期望的简报重点。
6. **challenge 任务包**要给：设计文档全文（这是审查对象，允许完整给出）、决策上下文摘要（为什么这么做，关键取舍）、明确请它审查的维度。
7. **评审任务包**（给 reviewer）要给四样：
   - **被评审的任务包原文**（对照基准，评审「计划对齐」靠它）
   - **执行者汇报全文**（执行摘要 + 变更清单 + 验证结果 + 上报项）
   - **查看变更的方式**：git 范围（BASE_SHA..HEAD_SHA，需 executor 先 commit）或精确的文件清单；未提交改动给 `git diff` 工作区说明
   - **重点审查维度**（可选）：如安全、并发、边界——默认全维度
   不要把 diff 本体粘进任务包；让 reviewer 自己用只读 git 命令看，任务包只给定位方式。

## 续作任务包（resume，原会话续作）

发给被 resume 的原 executor / 原 challenger。它已保有原任务包上下文，**只给增量**。
**禁止**把完整对话历史或原始任务包全文重粘进续作包。

```
## 目标
（裁决后定下的继续方向，一两句话，动词开头）

## 采纳的 findings（裁决后）
- [ ] <finding 1，≤120 字>
- [ ] <finding 2，≤120 字>

## 仍适用的约束
（原始任务包中仍然有效的硬性约束；没有就写「无额外约束，沿用原任务包」）

## 验证标准
（可机械判定的命令/期望输出，与修复内容对应）
```

> **严禁**：把 delta 续作包交给 fresh fallback Agent——fresh 没有原上下文，补不全。

## 重建任务包（fresh fallback）

只用于**明确证明**原会话不可恢复（stopped / 会话或 cwd 缺失 / receipt 不存在且无其他恢复索引，
见 SKILL.md「恢复决策顺序」）后的全新 Agent 启动。**必须自包含**，四要素一个都不能少：

```
## 目标
（完整重述本轮要完成的目标）

## 约束
（最新约束：原始约束 + 裁决后新增/修订的约束，全部列出）

## 相关文件
（精确路径清单；与原始一致，必要时补充裁决引入的新文件）

## 验收标准
（最新验证标准：原始验收 + 裁决后修订项）

## 采纳的 findings
（裁决后最终采纳的 findings 列表，已合入上述四要素；列出便于 fresh Agent 对账）

## 前置状态说明（可选）
（上一轮执行到哪一步、为什么 fallback——帮助 fresh Agent 判断进度，不替代四要素）
```

> **严禁**：把只含 findings 的 delta 续作包交给 fresh fallback Agent。
> 重建包发给 fresh Agent 时 phase 记 `fallback`，原因写进任务包与 state。

## challenger 第 2 轮任务包

发给**被 resume 的同一 challenger**（receipt keyed resume，见 references/workflows.md）：

```
## 修订后完整设计
（完整设计全文——这是第 2 轮的审查对象，修订处可标注）

## 第 1 轮裁决摘要
（你采纳了哪些 findings、驳回哪些及理由，≤150 字；让 challenger 知道修订的来龙去脉）

## 待审维度
（第 1 轮未覆盖/仍有分歧的维度；默认全维度复审）
```

## 修复后评审任务包（reviewer 复审）

发给 fresh reviewer 复审修复后的产出。**仍包含**：

- **被评审的原始任务包原文**（对照基准，评审「计划对齐」靠它）
- **执行者修复汇报全文**（改了哪些文件、跑了什么测试、如何验证）
- **查看变更的方式**：git 范围（BASE_SHA..HEAD_SHA，需 executor 先 commit）或精确的文件清单；
  未提交改动给 `git diff` 工作区说明
- **重点审查维度**（可选）：第 1 轮 verdict 未通过的主要方向（如安全、并发、边界）

## 反例

❌ 坏任务包：
> 用户反馈登录有 bug，请修复。以下是完整对话记录：（3000 字转储）

✅ 好任务包：
> **目标**：修复 `src/auth/login.ts` 中 session 过期后仍返回 200 的问题。
> **约束**：不改 `SessionStore` 公开接口；TypeScript strict 模式必须编译通过。
> **相关文件**：`src/auth/login.ts`（`verifySession` 函数，约 L45–80）、`src/store/session.ts`（只读参考）。
> **验收标准**：`npm test -- auth` 全绿；新增一个过期 session 返回 401 的用例。
